Runbook facts (13-RESEARCH "Runbook facts", all sourced; copy them, do not re-derive):
| Topic | Fact |
|---|---|
| Redeploy | `git commit --allow-empty -m "chore: redeploy" && git push`. A `workflow_dispatch` of `ci` deploys nothing (the deploy gate requires a push). |
| Roll back (preferred) | `git revert <bad-sha> && git push`, then watch `ci`, `deploy` and `live-smoke` on the revert SHA. |
| Roll back (alternative) | Actions -> the previous green `ci` run -> "Re-run all jobs" (same SHA/ref, rebuilds about 27 min, possible up to 30 days after the run). "Re-run" of only the `deploy` job works only within 1 day of that run, because `actions/upload-pages-artifact@v5.0.0` keeps the `github-pages` artifact for `retention-days: 1`. Re-runs use the original actor's privileges. A completed re-run of `ci` also triggers `live-smoke` with the old `head_sha` (verify on the first drill). |
| Read a live-smoke result | Run page summary (`github` reporter annotations); on failure the artifact `live-smoke-traces` (14 days) -> `pnpm --filter web exec playwright show-trace <trace.zip>`. Exit codes of `scripts/smoke.mjs`: 0 ok, 1 suite failed, 2 precondition (env gate: URL/SHA/host malformed or variables unset), 3 version never propagated within 10 minutes (deploy failed or CDN), 4 over the 5-minute budget (local three-target mode only). A skipped run means Pages is off or the `ci` run was not a green push to `main`. |
| Web E2E workers | `apps/web/playwright.config.ts` sets no `workers`: Playwright's default (half the logical CPUs). CI ubuntu-24.04 (4 vCPU): 2 workers ("using 2 workers" in every leg's log). Dev machine (16 logical): known-good `--workers=4` (10-23: 8 workers gave six 30 s timeouts; 4 was green). Retries: CI 1, local 0. |
| Smoke workers | `apps/web/playwright.smoke.config.ts`: `workers: process.env.CI ? 2 : 4`, retries 0, `failOnFlakyTests`, `globalTimeout` 300 s. |
| Extension E2E | `apps/extension/playwright.config.ts`: `workers: 1`, timeout 60 s, CI retries 1. |
| Vitest | Root `vitest.config.ts` projects (web, core, brand, scripts, web-browser, extension); no worker pin, Vitest defaults. CI: 349 files in 117-121 s. Dev: run it alone (a precommit test once failed under four parallel executors; Phase 15). |
| Fresh-profile rule | New InPrivate/Incognito window after every redeploy: Pages sends `Cache-Control: max-age=600` on HTML and the service worker is cache-first. |
| CDN | The Pages CDN ignores the `?_=` cache-busting query; the smoke's 10-minute poll relies on GitHub purging the CDN on deploy. Never raise the poll or add retries: measure (`smoke: <sha> live at <url> after <n> s` in the live-smoke log). |
| Analytics | The one GPC-off analytics spec sends at most one synthetic `/` pageview per smoke run (D-12; Umami may drop it as a bot). Read counts as a lower bound. |
| Dependabot policy | Majors of exactly the `dependency-name` entries in `.github/dependabot.yml` (written by 13-07: `@sveltejs/kit`, `@sveltejs/adapter-static`, `vitest`, `@vitest/*`, `vitest-browser-svelte`, `pnpm`, plus `@types/node` only if 13-01 Decision B = B-ignore; with B-accept the runbook says reopened `@types/node` major PRs are closed by hand with a Phase 14/16 comment) are ignored until Phase 16; minor/patch group PRs are reviewed through the `pnpm audit` gate, never merged blind (D-06/D-07); a github-actions PR is merged only when its CI is green (the gate tests compare pins across all workflows). |
| Variables | `PAGES_ENABLED` (deploy gate + live-smoke gate); `PUBLIC_SITE_URL` (origin only, e.g. `https://wolfwdavid.github.io`; every ci leg's env, live-smoke, extension-release); `BASE_PATH` (`/tran_real_estate`; root leg only, live-smoke, extension-release; set with `MSYS_NO_PATHCONV=1` from Git Bash); `PUBLIC_ANALYTICS_HOST` + `PUBLIC_ANALYTICS_WEBSITE_ID` (root leg; host also live-smoke); `PUBLIC_WEB3FORMS_KEY`, `PUBLIC_CONTACT_EMAIL` (root leg only); `EXTENSION_RELEASES_ENABLED` (extension-release). |
