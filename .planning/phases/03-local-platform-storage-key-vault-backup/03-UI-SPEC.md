# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Design intelligence: UI/UX Pro Max (`search.py --domain ux` for "form password input visibility toggle", "destructive confirmation dialog modal", "empty state error message toast", "settings security", and `--stack svelte` for "forms dialog accessibility", run 2026-10-04). **Adopted:** show/hide toggle on secret fields, a visible label on every input (never placeholder-only), loading-then-result feedback on every submit, a confirmation step before irreversible actions, success confirmation messages, errors announced through a live region and never shown by a red border alone, helpful empty states with a next action, and `aria-live` on dynamic content. **Rejected:** "use SvelteKit form actions / +page.server.js" (there is no server: static adapter, browser-only) and "auto-dismissing toasts" for security state (see Feedback model). No skill color or font output was used. Phase 2's approved palette, type scale and spacing are reused exactly.

**Sources legend:** `[CTX]` 03-CONTEXT.md (locked), `[P2]` approved 02-UI-SPEC.md (locked brand contract), `[REQ]` REQUIREMENTS.md / ROADMAP.md, `[CODE]` existing repo code, `[STACK]` CLAUDE.md stack, `[SKILL]` UI/UX Pro Max, `[D]` researcher discretion (CONTEXT "Claude's Discretion" or unaddressed UI detail).

### shadcn-svelte init contract (autonomous gate decision)

`components.json` is absent `[CODE]`. Phase 3 is the first phase that needs real primitives (focus-trapped dialogs, radio group, checkbox), so init happens now, in `apps/web/`.

1. `components.json` (in `apps/web/`): `tailwind.css = "src/app.css"`, `tailwind.baseColor = "stone"`, `typescript = true`, aliases `components = "$lib/components"`, `ui = "$lib/components/ui"`, `utils = "$lib/utils"`, `hooks = "$lib/hooks"`, `lib = "$lib"`, registry = shadcn-svelte official only.
2. **Ordering with Phase 2.** Phase 3 may execute in parallel with Phase 2 `[REQ]`. The Phase 2 token block in `app.css` must exist before Phase 3 UI work. If Phase 2's tokens plan has not landed, the Phase 3 init plan writes the Phase 2 `@theme` block itself, literal-for-literal from 02-UI-SPEC.md, so the parity test in `packages/brand` covers it. Never take init's generated `:root` oklch values.
3. **Post-init reconciliation of `app.css`:**
   - Keep Phase 2's `@theme { --color-*: initial; ... }` block as the only color source.
   - Delete init's `:root { --background: oklch(...) ... }`, `.dark { ... }`, `@custom-variant dark`, and the `@theme inline { --color-background: var(--background) ... }` mapping.
   - Add **alias tokens** (same hex as an existing Phase 2 token, no new colors) so copied component classes resolve. They are listed in the Color section and added to the parity test.
   - `tw-animate-css` (added by init) may stay only if every animation class it powers is wrapped in `motion-safe:`. Otherwise remove it and use the Motion rules below.
4. **Post-add reconciliation of component source** (copy-in means plain source edits `[STACK]`):
   - `button.svelte`: variants allowed are `default` (Phase 2 primary), `outline` (Phase 2 secondary), `ghost`, `destructive`, `destructive-outline` (new variant, defined below), and `link`. **Delete the `secondary` variant**, because shadcn's `secondary` is a fill while Phase 2's `secondary` token is sage ink text, so the class `bg-secondary` would paint a sage block. Sizes: `default` = 48px tall, `icon` = 44x44px. Delete the `sm` and `lg` sizes (`sm` breaks the 44px target rule).
   - Dialog and alert-dialog overlay: replace `bg-black/50` with `bg-foreground/60` (espresso scrim).
   - Every `rounded-*`, `shadow-*`, `ring-*` and `text-*` size class is mapped to Phase 2 tokens (`--radius-md` for controls, `--radius-lg` for dialogs and cards, `--shadow-card-hover` for dialogs, `outline: 2px solid var(--color-ring); outline-offset: 2px` for focus). Remove shadcn's `ring-[3px] ring-ring/50` focus treatment and any `aria-invalid:ring-destructive/20` translucent rings.
   - No raw hex and no Tailwind palette classes in any component. The `--color-*: initial` guardrail makes them fail to compile into anything.
5. A lint/grep check (extending Phase 2's banned-terms approach) fails CI if `bg-secondary`, `bg-black`, `dark:`, or `ring-ring/` appear under `src/lib/components/ui/`.

## Shape, Elevation, Motion

Phase 2 tokens `[P2]`: `--radius-md` 8px (buttons, inputs), `--radius-lg` 16px (provider cards, callouts, dialogs, notice), `--radius-full` (badges, radio), `--radius-sm` 4px (checkbox). `--shadow-card` on provider cards; `--shadow-card-hover` on dialogs. `--ease-out`, `--duration-fast` 150ms, `--duration-base` 200ms.

- Dialog open/close: overlay and content fade `opacity` 0→1 over 150ms, content `transform: scale(0.98)` → `scale(1)` over 200ms, all wrapped in `motion-safe:`. Under `prefers-reduced-motion: reduce`, dialogs appear and disappear instantly.
- In-flight buttons (Saving, Unlocking, Checking file, Importing) show Lucide `LoaderCircle` 16px spinning (`animate-spin`, `motion-safe:` only; under reduced motion it is static) plus the in-progress label. The button keeps its width (`min-width` set to its rest width) so the layout does not jump.
- Provider cards do **not** lift on hover (they are not links). No scroll reveals.
- The import preview panel appears in flow (no height animation).

## Layout & Route Contract

### `/settings/` page (prerendered shell, `(app)` group) `[CTX]`

- `h1` "Settings" (Display), lead paragraph (Body, `muted-foreground`, max 640px).
- **Section nav** `<nav aria-label="Settings sections">` with eyebrow "On this page" (Label 14/600 uppercase, `secondary`) and a `<ul>` of 5 in-page links: API keys → `#api-keys`, Key security → `#key-security`, Backup and restore → `#backup`, Storage → `#storage`, Install the app → `#install`. Each link is 44px tall.
  - Below 1024px: the nav sits under the lead as a vertical list, followed by 48px space.
  - At 1024px and up: two columns `240px 1fr` with a 64px gap; the nav is `position: sticky; top: 24px` in the left column; content column max 640px.
  - No scroll-spy and no current-section highlight (avoids JS motion and false state).
- Each section is `<section id="…" aria-labelledby="…-heading">` with an `h2` (Heading). Sections are separated by 64px (48px below 768px) and a 1px `border` divider. Anchor targets get `scroll-margin-top: 16px` `[P2]`.
- Section order is fixed: API keys → Key security → Backup and restore → Storage → Install the app `[CTX]`.
- **Hydration:** the prerendered HTML shows each section's static copy, plus a status line reading "Checking this browser…" (Label 14/400, muted) where live state goes. All vault, IndexedDB, `navigator.storage`, and install detection runs in `onMount`. No SSR access to browser APIs.
- **Existing CSP fixture:** the current placeholder renders `data-testid="csp-transition-toggle"` / `csp-transition-target` used by the Phase 1 CSP E2E `[CODE]`. The plan must keep an equivalent transition-driven element (or move the fixture and update the spec in the same commit). Do not delete it silently.

### App notice slot (`(app)` layout) `[CTX non-blocking banner]`

- `AppNotice` renders as the **first child of `<main>`** in `(app)/+layout.svelte`. It is in flow (pushes content down), never fixed or overlaid. Container: `--container-page`, page gutters, 16px top margin.
- At most **one** notice shows, by priority: (1) **Keys locked** (only if a passphrase-locked vault exists and is locked; suppressed on `/settings/`, where the unlock form is), then (2) **Backup overdue**.
- Markup: `<div role="region" aria-labelledby="app-notice-title">` (not `<aside>`, which axe flags inside `main`). It is not a live region: it is present on load, not an announcement.
- Visual: `accent-surface` background, 4px `primary` left rule, `--radius-lg`, padding 16px (24px at 640px and up). Lucide icon 20px `foreground` `aria-hidden` (`Lock` for locked, `HardDriveDownload` for backup), title Body 16/600, body Body 16/400, actions row (8px gap below 640px, 16px from 640px).
- Marketing routes never show it and never import the vault or Dexie `[P2 CSP & performance]`.

### Backup reminder rule `[CTX]` `[D]`

- `lastBackupAt` is stored in a small pref (runed `PersistedState`, or the Dexie meta table). It is set on every successful export.
- Show the reminder when **at least one user record exists** and `now − max(lastBackupAt ?? firstRecordCreatedAt) ≥ 7 days`.
- **"Remind me tomorrow"** snoozes it for 24 hours (`backupReminderSnoozedUntil`). There is no permanent dismiss: eviction risk is first-class `[CTX specifics]`.
- Day counts are whole days, computed with date-fns `differenceInCalendarDays`.

### Focus management

- Opening any dialog moves focus to: **the Cancel button** in destructive alert-dialogs; **the first input** in the passphrase dialogs. `Escape` closes and acts as Cancel. Focus returns to the trigger on close. Destructive alert-dialogs do **not** close on overlay click (bits-ui AlertDialog default); the passphrase dialog does.
- After "Choose backup file" succeeds, focus moves to the preview panel's `h3` ("Review this backup", `tabindex="-1"`).
- After "Replace key", focus moves to that provider's key input.
- After a failed submit, focus moves to the first invalid field.
- After "Forget all keys" confirms, focus moves to the API keys `h2` (`tabindex="-1"`), because the trigger's surrounding state changed.

### Feedback model `[D]` `[SKILL submit-feedback, confirmation-messages, error-messages]`

1. **Inline, persistent status** next to the control that changed (badge, status line, result line, error alert). It stays until the next relevant action. No auto-dismiss.
2. **Polite announcement** of the same fact through `LiveAnnouncer` (wording in the table below). `role="alert"`/assertive is not used anywhere in Phase 3 `[CTX "polite live region"]`; field errors are reached by moving focus to the invalid field.
3. **Cross-tab changes** arriving through `BroadcastChannel` (forget, lock, mode change) update the UI in the other tab and announce there too.

## Security & Privacy UI Rules `[CTX]`

- Key values never appear in: the DOM after save (only last4), `console.*`, error messages, announcements, URLs (no query/hash state for keys), `title`/`aria-label` attributes, analytics, backup files, or Svelte devtools-visible `$state` on shared components (keep raw values inside the vault module).

Prefer an `<a download href={objectURL}>` click, which navigates to nothing and does not require `connect-src blob:`. Revoke the object URL right after the click. The Phase 1 CSP oracle must stay green; if any directive must change, the plan states it explicitly.
- Service worker and manifest: served from `'self'` under the base path `[CTX]`. The service worker never caches or touches requests to provider hosts.

## Accessibility Contract (Phase 3 additions to Phase 2's) `[P2]` `[SKILL]`

- The axe E2E covers `/settings/` in these states, on both root and sub-path bases: empty (no keys), keys saved, remember mode with locked vault, import preview open (Merge and Replace), each dialog open, and the backup notice visible on a portal route. Zero violations with tags `wcag2a, wcag2aa, wcag21aa, wcag22aa`.
- Heading order: h1 Settings → h2 sections → h3 provider names / sub-groups. Dialog titles are the dialog's accessible name (bits-ui wires `aria-labelledby`/`aria-describedby`).
- Every input has a visible `<label for>`. Every radio group is a `fieldset` + `legend` (or bits-ui equivalent with `aria-labelledby`). The required checkbox has `aria-describedby` → its error.
- Focus never lands on a hidden element. Dialogs trap focus, `Escape` closes, and focus returns to the trigger. No keyboard traps elsewhere.
- Status is never conveyed by color alone: badges have text, errors have text + icon, checked state has a glyph.
