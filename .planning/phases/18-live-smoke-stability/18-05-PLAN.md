<objective>
Owner-gated proof of SMOKE-07: three sequential pushes to main, each followed by its own green chained live-smoke run. Executors and subagents NEVER push: each push is a checkpoint where the orchestrator asks the owner for explicit approval and, on approval, performs the push itself.

Purpose: Roadmap criterion 2 (three consecutive green chained runs, zero retries, no 429 ignored) and confirmation that criteria 3 and 4 hold in the wild.
Output: three recorded run ids, 18-VERIFICATION.md, local commits for the evidence.

Hard rules:
- Every push needs the owner's explicit approval each time. Never push the next one until the previous chained live-smoke run has finished (ci takes 27 to 33 minutes, then the smoke 1 to 2 minutes; pushing earlier cancels the earlier ci and no chained run exists). A superseded exit-0 run or a re-run does not count toward the three.
- If any of the three runs shows a 429 (exit 2 or a 429 line in its log): stop, fix the root cause (reduce volume further; `workers: 1` is the reserve option, still no sleeps, retries, toPass or raised timeouts), and start a NEW set of three. Never re-dispatch in a loop; at most one re-dispatch per the RUNBOOK, and it does not count.
- Never dispatch a smoke by hand to fill the count. The live site is not loaded beyond what the chained workflow does.
- Stage explicit paths only; never .planning/config.json; never git add -A. Commit messages describe the change only: no co-author trailer, no mention of AI assistants anywhere. Never write text of the form NAME_KEY=value in docs. Read-only gh commands only (run list, run view --log).
- The planning-only commits listed by `git log origin/main..HEAD` (milestone v1.2 start, requirements, roadmap, this phase's research and plans) go up with the FIRST proof push; tell the owner this in checkpoint 1.
</objective>
