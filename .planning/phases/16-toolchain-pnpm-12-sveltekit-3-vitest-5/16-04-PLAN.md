<objective>
Migration 1 of 3: pnpm 11.27.0 to 12.18.0 (TOOL-01), D-01 order. Research label 16-01.

Purpose: pnpm 12 is a native Rust binary and sets `npm_execpath` to `pnpm.exe`, so four scripts that spawn `node $npm_execpath ...` crash with ERR_UNKNOWN_FILE_EXTENSION (reproduced in the research spike). The pin is therefore a code change, a lockfile change and a test rewrite, not a one-line bump.
Output: shared pnpm-cmd helper + test, four call sites on it, pin to pnpm@12.18.0, exactly one lockfile regeneration, supply-chain and launch-audit tests rewritten (no hardcoded 11.27.0), docs corrected, a green verify + smoke:local, an owner-approved push with a green live smoke.

Two-commit rule (D-05): Task 1 commits the helper, its test and the four call-site refactors on their own as `refactor(scripts): share one pnpm spawn helper`, verified under pnpm 11 (the helper's `.js` branch) before the pin exists, so it lands first and an interruption loses nothing. Task 2 commits the pin and the single lockfile regeneration together with the rewritten lockfile and launch-audit tests and the docs. The invariant that must hold: no commit has the pnpm 12 pin without the helper, i.e. the helper commit is an ancestor of the pin commit (research finding 1).

Hard rules: D-01 no second major; D-03 no retries/raised timeouts; D-05 commit message focused on the change, no `Co-Authored-By`, no AI mention; machine notes as in 16-01 (a global pnpm 11 self-switches to 12.18.0 once the pin is set; corepack.cmd pnpm downloads the 12.18.0 binary; stage-by-stage verify; 7-minute call cap; rebuild all three targets after the last commit). Package legitimacy: pnpm itself is the one package changed; slopcheck was unavailable, so treat the bump as [ASSUMED]-class and use the lockfile-diff review below as the compensating control. Do NOT add pnpm to `allowBuilds` (that setting governs dependencies, not the manager).
</objective>
