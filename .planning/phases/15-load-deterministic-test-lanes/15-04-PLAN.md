## Decisions (recorded at planning time)

- **Q1:** Playwright raises are in TEST-02's scope. Annotation only in Phase 15; values never change here (a value change needs its own measured root cause, which is out of scope).
- The cited number is the governing test's duration (the wait cannot exceed it), max across projects in the report. <interfaces>
From scripts/lib/test-lane-rules.mjs (15-02):
- `playwrightTimeoutFindings(path, text) -> Finding[]` with `{ path, line, rule: 'unannotated-raise', detail }`
- Raised = `test.setTimeout(x)` with x > 30000 or non-literal; `*.describe.configure({ timeout })` > 30000 or non-literal; every `test.slow(...)`; any other call's object option `timeout` > 5000 or non-literal.
- Annotated = the leading comment block of the option property, the enclosing statement, or (for an identifier value) the `const` declaration matches BOTH `/\bmeasured\b[^\n]*?\d+(?:\.\d+)?\s*(?:ms|s|min)\b/i` and `/\bcause\b/i`.

Annotation template (keep `measured <n> s` on ONE line; `Cause:` on the next):
```ts
// Timeout: measured <max> s for "<test title>" (<project>, 4 workers, e2e-report 449ecc5, 2026-11-06).
// Cause: <what the slow part is, e.g. "the keyless sample streams a full 4-section draft and renders the preview">. <value/1000> s keeps a <ratio>x margin.
```
For `test.slow()`: `// Timeout: test.slow() (90 s); measured <max> s for "<title>" (...). Cause: <...>.`
Hoisting (Pattern 4): when a file repeats the same raise >= 2 times, add one file-level `const <NAME>_MS = <value>;` (UPPER_SNAKE, e.g. `AI_FLOW_MS`) with the annotation above it, and replace each literal with the constant. The cited duration is the max over all tests that use it.
</interfaces>
