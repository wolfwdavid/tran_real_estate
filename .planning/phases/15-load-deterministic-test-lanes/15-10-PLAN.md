## Decisions (recorded at planning time)

- Pressure level: 16 burner threads on the 16-CPU dev machine (`os.availableParallelism()`), normal priority, via `scripts/cpu-burn.mjs`. 10-23 recorded 0 failures at 16 burners; 40 burners plus llama-server produced pure starvation timeouts and is not a fair zero-failure target.
- Vitest has no `--repeat-each` (Vitest 4 CLI); the Vitest files a deferred-items file names (`LOAD_SENSITIVE_VITEST`) all sit in the serial lane, so "repeat 3" for them = three consecutive `pnpm vitest run --project "*-serial"` runs.
- Any failure in any step: root-cause it (lessons 2026-10-13: reproduce under artificial delay before calling it a flake). A fix is a new commit, so the protocol restarts at Step 1 on the new SHA; record the failed attempt and its root cause in the evidence file under `## Attempts`. Never add a retry or raise a timeout to get green (the 15-09 guard would also fail).
- Evidence date `DD` in the file name is the UTC date when Step 1 starts.
