# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: a **light** UI phase. Phase 4 builds the data primitives that every portal (Phases 6-9) uses, plus additions to Settings and the `(app)` layout. It adds no portal screens.
> Design intelligence: UI/UX Pro Max (`src/ui-ux-pro-max/scripts/search.py --domain ux` for "progress bar usage meter", "confirmation dialog destructive cost", "badge status chip label", "error message recovery", "rate limit loading retry", "number formatting relative time", run 2026-10-04). **Adopted:** show a clear next step with every error (a "Try again" action plus a help link), confirm before any action you can't undo (here, spending money), announce errors to screen readers and never show them by color alone, show loading feedback for anything over 300ms, relative dates ("2 hours ago") with a locale-aware fallback, and thousands separators. **Rejected:** `role="alert"` for errors (Phase 3 locked a polite-only live region, so this phase keeps it) and a step-style progress bar (a monthly usage meter is a measurement, not a step-by-step flow; see `CallMeter`). The skill produced no color or font output. Phase 2 tokens are reused exactly.

**Sources legend:** `[CTX]` 04-CONTEXT.md (locked), `[P2]` approved 02-UI-SPEC.md, `[P3]` approved 03-UI-SPEC.md, `[REQ]` REQUIREMENTS.md / ROADMAP.md, `[CODE]` existing repo, `[STACK]` CLAUDE.md, `[SKILL]` UI/UX Pro Max, `[D]` researcher discretion (CONTEXT "Claude's Discretion", or a UI detail that upstream documents don't cover).

**Honesty rules for this phase (apply to every string below):**
1. Tran never bills anyone. Overage is always described as "$0.20 per call, billed by RentCast to your card", and only "if your RentCast account has a card on file".
2. The meter counts **calls made from this browser**. It never claims to be RentCast's own count.
3. Estimates are called "estimates". The words "appraisal", "appraise", "value" as a noun for a property's worth, and "guarantee" never appear (Phase 2 banned-terms grep).
4. Usage state is never shown by color alone. Every meter state has its own text and its own icon.
5. "Sample data" must be unmistakable on every surface that renders fixture rows.

## Typography

Reused exactly: **4 sizes** (14 / 16 / 24 / 40) and **2 weights** (400, 600) `[P2]` `[P3]`.

| Role | Family | Size | Weight | Line Height | Phase 4 usage |
|------|--------|------|--------|-------------|---------------|
| Label | Inter | 14px | 600 (chip text, meter numbers in the compact bar) / 400 (meter sub-line, helper text, test-result line, cost note under dialogs, "Not counted" line) | 1.4 | `ProvenanceChip`, `NewSinceBadge`, meter sub-lines, Settings helper text |
| Body | Inter | 16px | 400 (paragraphs, GatewayError body, dialog body, the cost part of a `CostLabel`) / 600 (button labels, meter headline "12 of 50 calls used this month", GatewayError title, sub-group `h3`s, field labels) | 1.6 | Everything else |
| Heading | Fraunces | 24px | 600 | 1.25 | The new Settings `h2` "RentCast usage" and every dialog title |
| Display | Fraunces | 40px | 600 | 1.1 | Not used in Phase 4 (the Settings `h1` already exists) |

Rules:
- **Every count, dollar figure, and date in a meter, cost label, chip or dialog uses `font-variant-numeric: tabular-nums`** so numbers don't shift width as they change `[P2]`.
- Numbers are formatted with `Intl.NumberFormat('en-US')` (so "1,000"). Dollar amounts use `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })`, so "$0.20" and "$2.00", never "$.2" `[SKILL number-formatting]`.
- **`CostLabel` weight split:** inside a button, the verb is Body 16/600 and the parenthetical cost is Body 16/**400**, for example **Search rentals** (1 call). Both sit in the same text run, so the accessible name is "Search rentals (1 call)".
- No text below 14px. No Fraunces below 24px `[P3]`.

### `CallMeter` `[CTX]` `[REQ DATA-02]`

Inputs: `used` (billed calls this month), `unbilled` (404 no-result requests this month), `cap`, `planLimit` (constant 50, the free Developer plan `[STACK]`), `resetsAt` (first day of next month, 00:00 UTC), `variant: 'full' | 'compact'`.

**Semantics:** a `<div role="group" aria-labelledby="{id}-headline">`. The bar is **decorative** (`aria-hidden="true"`). The visible text is the source of truth. This avoids `role="meter"`/`progressbar` support gaps, and screen-reader users get the same sentence sighted users read.

**States** (computed in `packages/core`, pure and unit-tested; `U` = used, `C` = cap, `P` = 50):

| State | Condition | Fill color | Icon (20px full, 16px compact, `aria-hidden`) | State line (always visible text) |
|-------|-----------|------------|-------------|----------------|
| OK | `C − U ≥ 6` | `secondary` | `Gauge` `secondary` | none in compact; full shows the standard sub-line only |
| Near cap | `1 ≤ C − U ≤ 5` | `primary` | `CircleAlert` `foreground` | "{C − U} calls left before your cap." (singular "1 call left before your cap.") |
| At cap | `U ≥ C` and `U < P` | `primary` | `CirclePause` `foreground` | "You've reached your cap. Tran asks before each extra call." |
| Past plan limit | `U ≥ P` | `destructive` | `CircleAlert` `destructive` | "You're past the 50 calls in RentCast's free plan. If your RentCast account has a card on file, RentCast bills each extra call at $0.20, charged to your card." |

(If `C > P`, "Past plan limit" takes priority once `U ≥ P`. Thresholds live in one exported constant.)

**Full variant (Settings):**
- Headline (Body 16/600, `id="{id}-headline"`): "{U} of 50 calls used this month".
- Track: 100% width × 8px, `surface` fill, 1px `input` border, `--radius-full`. Scale = `max(50, C, U)`. Fill width = `U / scale`.
- **Cap marker:** a 4×16px `foreground` bar at `C / scale`, with a Label 14/400 `muted-foreground` caption "Cap {C}" directly under it. Its horizontal position is clamped so the caption never overflows at 375px. If `C > 50`, a second 4×16px marker sits at `50 / scale` with the caption "Free plan: 50" in `muted-foreground`, and the two markers' captions stack (cap caption first) when they would overlap.
- Sub-line (Label 14/400 `muted-foreground`, tabular): "Cap: {C} · {max(C − U, 0)} left before your cap · Resets {Mon D} (UTC)", for example "Cap: 40 · 28 left before your cap · Resets Nov 1 (UTC)".
- State line (if the state has one): icon + text, Body 16/400 `foreground`.
- "Not counted" line (only when `unbilled > 0`), Label 14/400 muted: "Not counted: {n} searches with no results. RentCast bills only requests that return data."
- Scope note (always, Label 14/400 muted): "This counts calls made from this browser. Calls from other devices or the RentCast dashboard aren't included, and RentCast's own billing cycle may start on a different day. Your RentCast dashboard has the official count."

**Compact variant (`DataStatusBar`):**
- Row: icon (state icon, 16px) · text "RentCast calls: **{U} of 50** this month" (Body 16/400, numbers at 600, tabular) · 96×8px track with cap marker (no captions) · "Cap {C}" (Label 14/400 muted) · state text for Near / At / Past (Label 14/600 `foreground`: "{n} left", "Cap reached", "Past free 50") · link "Usage and cap".
- Below 640px the row wraps: line 1 = icon + text + track; line 2 = cap + state text + link.
- `aria-labelledby` points at the text node, so the group reads "RentCast calls: 12 of 50 this month".

**Threshold announcements** (through Phase 3's `LiveAnnouncer`, once per crossing per page session, never on load): see the announcements table.

### `CostLabel` `[CTX]` `[REQ DATA-02]`

- Renders the parenthetical cost **inside** the action's button label, from `gateway.estimateCost(request)`. It is recomputed whenever the request or the cache state changes. It is never hard-coded by the caller.
- Formats (exact strings): "(1 call)" · "({n} calls)" · "(0 calls · cached)" · "(0 calls · sample data)" in sample mode · "(0 calls)" for Test key.
- The cost text is Body 16/400 at the same size as the verb, so it is part of the button's accessible name. It is never a tooltip, never icon-only, and never shown only on hover.
- **Cached reads:** when the cost is 0 because the cache is fresh, the label reads "(0 calls · cached)". The adjacent `ProvenanceRow` shows when that data was fetched.
- **At or past cap:** the label still shows the real cost, for example "(1 call)". The cap prompt is the dialog's job. The label is not rewritten into a warning.

### `CapConfirmDialog` `[CTX]` `[REQ DATA-03]`

Opens when the gateway throws `BudgetCapReached` for a user-initiated call. It wraps Phase 3's `ConfirmDialog` (alert-dialog) pattern: `card` content, `--radius-lg`, 24px padding, max width 480px, footer [Cancel, Confirm] right-aligned from 640px and stacked full width below 640px `[P3]`.

- **Per call, never remembered** `[CTX]`. There is no "don't ask again" checkbox, no session flag, and no timer. Confirming grants a single-use allowance that the gateway consumes on that one request. A unit test proves a second call opens the dialog again.
- Not used by the alerts scheduler. The scheduler never goes past the cap (see `DueSearchesDialog`).
- **Variant A, within plan** (`U < 50` after the call): confirm button `default` (terracotta).
- **Variant B, past plan** (the call would be number 51 or later this month): confirm button `destructive`.
- Body contains a small **fact list** (`<dl>`, Body 16, tabular): "Used this month: {U} of 50" · "Your cap: {C}" · "This action: 1 call".
- In progress: the confirm button reads "Spending…" with a spinner, both buttons are disabled, and `Escape` is ignored until the request settles. The dialog then closes, and the result renders where the action's result goes.
- `window.confirm` stays banned by lint `[P3]`.

### `CapAboveLimitDialog` `[CTX "typed confirmation above plan limit"]` `[D]`

CONTEXT says both "1..50" and "values above the plan limit need a typed confirmation". With a 50-call free plan, those only fit together one way, which this contract adopts:
- **1 to 50:** saved directly with **Save cap**.
- **51 to 1,000:** allowed only through this dialog, because every call past 50 can be billed. 1,000 is the upper bound (the Foundation plan's monthly size `[STACK]`), so a typo like "4000" can't authorize thousands of billable calls.

Dialog: alert-dialog with one input. Label "Type overage to confirm" (Body 16/600), a 48px input (`autocomplete="off"`, `autocapitalize="off"`, `spellcheck="false"`), and a match that ignores case and trims spaces. The confirm button stays enabled. Submitting without a match shows the field error, so validation is never shown only by a disabled button `[P3]`. Confirm **Set cap to {N}** (destructive). Cancel **Keep cap at {old}** (outline, initial focus).

### `ProvenanceChip` and `ProvenanceRow` `[CTX]` `[REQ DATA-01, DATA-04]`

`ProvenanceChip` is a Phase 3 `badge`: `--radius-full`, padding 4px 8px, icon 14px `aria-hidden` + text Label 14/600, 4px gap. It is a `<span>`. The text carries the full meaning.

| Variant | When | Fill / text | Icon | Text |
|---------|------|-------------|------|------|
| **Sample** | `provenance.source === 'sample'` | `accent-surface` / `foreground`, plus a 1px `border-strong` outline so the chip stays visibly separate when it sits on an `accent-surface` region such as the sample `DataStatusBar` (the text, not the outline, carries the meaning) | `FlaskConical` | "Sample data" |
| **Live** | `source === 'rentcast'`, `stale === false` | `secondary-surface` / `secondary` | `Database` | "RentCast · as of {relative}" |
| **Stale** | `source === 'rentcast'`, `stale === true` | `surface` / `foreground` | `History` | "RentCast · as of {relative} · may be out of date" |

- `{relative}` is wrapped in `<time datetime="{ISO fetchedAt}">`. Under 1 minute → "just now". Under 7 days → date-fns `formatDistanceToNowStrict(…, { addSuffix: true })` (for example "2 hours ago", "3 days ago"). 7 days or older → "Sep 28" (`Intl.DateTimeFormat` month short + day; add the year if it isn't the current year).
- A repeat request served from cache carries the **original** `fetchedAt` `[CTX]`, so the chip never pretends cached data is new.
- The chip wraps as a whole unit (`white-space: nowrap` inside, the row wraps around it). At 375px, the stale text may wrap inside the chip onto two lines. The chip then uses `--radius-lg` instead of full, so it never clips.

`ProvenanceRow` = chip + (live/stale only) **Refresh (1 call)** button (outline variant, Lucide `RefreshCw` 16px, 48px tall `[P3]`), 8px gap, wrapping below 375px. Refresh calls `gateway.refresh(key)`, bypassing the TTL for that one request `[CTX]`. While running it reads "Refreshing…". It goes through the cap check like any call. No Refresh button appears in sample mode.

### `DueSearchesDialog` and the alerts scheduler UI `[CTX]` `[D]`
