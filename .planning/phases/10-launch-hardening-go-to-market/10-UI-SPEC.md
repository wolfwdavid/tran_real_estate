# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Design intelligence: UI/UX Pro Max (`src/ui-ux-pro-max/scripts/search.py --domain ux` for "onboarding tour first run skip progressive", "progress indicator steps wizard", "form submit feedback success error", "inline validation", "empty state", "number input format currency", "disabled button submit loading", and `--domain landing` for "waitlist lead capture minimal form" and "SEO tool calculator page", run 2026-10-04). **Adopted:** a tour the user can skip, go back in, and leave at any point (no locked overlay), a visible step indicator, the shortest possible form (waitlist = one field), loading then success or error after every submit, an error with a next step, validation on blur rather than only on submit, helpful empty states with an action, thousands separators, and a visible label on every input. **Rejected:** countdown timers, a "waitlist count", scarcity and referral mechanics, and a sticky form (all conflict with the locked "no fabricated metrics, no promises" rule), the dark "anticipation" palette (Phase 2 tokens are locked), SvelteKit form actions (no server), and opacity-only disabled states (Phase 3 rule). No skill color or font output was used. **No new hex values.**

**Sources legend:** `[CTX]` 10-CONTEXT.md (locked), `[P2]` approved 02-UI-SPEC.md, `[P3]` approved 03-UI-SPEC.md, `[P4]` approved 04-UI-SPEC.md, `[P5]` approved 05-UI-SPEC.md, `[C6]` `[C7]` `[C8]` `[C9]` phase CONTEXT files, `[REQ]` REQUIREMENTS.md / ROADMAP.md (GTM-01..04), `[STACK]` CLAUDE.md, `[PIT]` research/PITFALLS.md, `[SKILL]` UI/UX Pro Max, `[D]` researcher discretion (CONTEXT "Claude's Discretion", or a UI detail upstream does not cover).

**Codebase state at research time (2026-10-04):** only Phase 1 is built. `apps/web/src/app.css` has an empty `@theme`; routes are the Phase 1 placeholders. Every Phase 2-9 component named below (`ButtonLink`, `PortalCard`, `SiteFooter`, `LegalPage`, `LiveAnnouncer`, `ProviderKeyCard`, `KeyTestResult`, `CapEditor`, `SectionError`, `StorageBlockedAlert`, `DataStatusBar`, the Phase 6 affordability component, `core.finance`) is consumed, never re-implemented. Phase 10 executes after Phases 1-9 `[REQ]`.

**Copy rules for this phase (apply to every string below):**
1. Calculators are "general guidelines, not financial advice". They never call a result good, bad, safe, or a deal.
2. No programmatic city or ZIP pages. SEO pages are the four calculators plus their hub only `[CTX]`.
3. No fabricated metrics, testimonials, user counts, ratings, or "join N others" lines `[P2]`.
4. Waitlist copy never promises features, release dates, or schedules.

## Typography

Reused exactly: **4 sizes** (14 / 16 / 24 / 40) and **2 weights** (400, 600) `[P2]`. Phase 10 introduces no UI size and no UI weight.

| Role | Family | Size | Weight | Line Height | Phase 10 usage |
|------|--------|------|--------|-------------|----------------|
| Label | Inter | 14px | 600 (eyebrows "Get started" / "Free calculator" / "Waitlist", "Step 2 of 3", status badges, footer column headings) / 400 (helper text, field errors, character counter, breadcrumb, result definitions, "Example numbers" note, form privacy notes) | 1.4 | Small meta and status |
| Body | Inter | 16px | 400 (paragraphs, input text, FAQ answers, result terms, tour step bodies) / 600 (button labels, field labels, tile titles, tour action text, result values in the `<dl>`, FAQ questions as `h3`) | 1.6 | Everything else |
| Heading | Fraunces | 24px | 600 | 1.25 | Section `h2`s ("Get started", "Your results", "How it's calculated", "Questions", "Join the renter waitlist"), setup step `h2`s, tour step titles when rendered as `h3` inside the guide panel, **the headline result value** (e.g. "6.24%") |
| Display | Fraunces | 40px | 600 | 1.1 | The single `h1` per page (tool pages, `/tools/`, `/feedback/`, `/setup/rentcast/`) |

Rules:
- Tour step titles are `h3` elements styled as **Heading** so the guide reads as a self-contained editorial object (the same exception Phase 2 made for portal-card titles) `[P2]`.
- The headline result value uses Heading (Fraunces 24/600) with `font-variant-numeric: lining-nums tabular-nums`. Every other number in a calculator, counter, or meter uses Inter with `tabular-nums` `[P2]`.
- Numbers: `Intl.NumberFormat('en-US')`. Money outputs are whole dollars ("$15,600", "−$120"). Percent outputs use two decimals ("6.24%"). DSCR uses two decimals with no unit ("1.04"). Negative values use the true minus sign U+2212 and the word "negative" in the adjacent text, so the sign is never the only cue.
- `text-wrap: balance` on `h1`/`h2`; `text-wrap: pretty` on paragraphs `[P2]`.
- No text below 14px. No Fraunces below 24px `[P3]`.

**OG card type scale (asset only, 2× the UI roles):** Label 28px Inter 600 (letter-spacing 0.06em, uppercase) · Body 32px Inter 400 · Heading 48px Fraunces 600 · Display 80px Fraunces 600 (line height 1.1). No other sizes appear on the card.

## Shape, Elevation, Motion

Phase 2/3 tokens `[P2]` `[P3]`: `--radius-md` 8px (buttons, inputs, portal tiles), `--radius-lg` 16px (guide panel, calculator cards, form panels, callouts, tool cards), `--radius-full` (step discs, progress segments, badges). `--shadow-card` on the guide panel, calculator cards, and tool cards; `--shadow-card-hover` on tool-card hover. `--ease-out`, `--duration-fast` 150ms, `--duration-base` 200ms.

- Tour step changes, form state changes (idle → sending → success), and calculator result updates are **instant**: no slide, height, or count-up animation. A count-up would invite a false "live data" reading `[P4]`.
- Portal tiles: hover/`:focus-within` changes the fill to `accent-surface` over 150ms. No lift (tiles are buttons inside a panel, not cards).
- Tool cards on `/tools/`: Phase 2 portal-card lift (`translateY(-2px)` + `--shadow-card-hover`, 200ms) `[P2]`.
- In-flight submit buttons show Lucide `LoaderCircle` 16px (`motion-safe:animate-spin`) and keep their rest width `[P3]`.
- Under `prefers-reduced-motion: reduce`, every transform is removed and durations go to 0ms `[P2]`.

## Accessibility Contract (Phase 10 additions) `[P2]` `[P3]` `[SKILL]`

- The axe E2E (tags `wcag2a, wcag2aa, wcag21aa, wcag22aa`, zero violations, root and sub-path bases) runs on **every prerendered route in the keyless state and the mocked-key state** `[CTX]`, plus: the landing guide at step 0, each tour step for each portal, and the compact row; each calculator in empty, example-filled, invalid-field, and (DSCR) not-applicable states; the waitlist and feedback forms in open, invalid, sending, success, error, and coming-soon states; `/setup/rentcast/` with no key, a saved untested key, and a tested key.
- Heading order: one `h1` per page. Guide: `h2` → `h3` step titles. Tool pages: `h1` → `h2` sections → `h3` FAQ questions. Setup: `h1` → `h2` steps.
- The guide is never a dialog, never traps focus, never overlays content, and can be hidden from every state in one action `[CTX "no modal trap"]`.
- The breadcrumb is a `nav` with a unique label ("Breadcrumb"), so the page has three distinct navigation landmarks: Portals, Breadcrumb, Footer.
- Calculator inputs have visible labels with the unit in the accessible name; errors are text + icon and linked through `aria-describedby`; the results card is a labeled section, not a live region.
- Status is never color-only: progress shows "Step n of 3"; badges have text; negative values carry the word "negative"; success and error panels have titles and icons.
- The honeypot is `display: none`, so it never enters the tab order or the accessibility tree.
- 375px: no horizontal page scroll on any new route (the Phase 2 viewport test gains the 7 new routes); tiles, action rows, form rows, and result rows stack; long formula lines wrap (`overflow-wrap: anywhere` on `<dd>`).
- 200% zoom and WCAG 1.4.12 text spacing hold; no fixed heights on text containers (tile and textarea heights are minimums).
