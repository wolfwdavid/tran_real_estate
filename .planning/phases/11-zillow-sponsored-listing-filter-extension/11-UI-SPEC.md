# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Design intelligence: UI/UX Pro Max (`search.py --domain ux` for focus states, keyboard navigation, reduced motion, disabled/dimmed contrast, touch targets, and touch spacing, run 2026-10-04). Everything the skill returned is consistent with the locked Phase 2 tokens. No skill palette or font was adopted. The Phase 2 tokens are the only color source.

**Sources legend:** `[CTX]` 11-CONTEXT.md (locked), `[REQ]` REQUIREMENTS.md / ROADMAP.md (EXT-01..04), `[P2]` 02-UI-SPEC.md (approved tokens), `[P3]` 03-UI-SPEC.md (PWA "T" mark), `[STACK]` CLAUDE.md stack notes (WXT 0.21.4, `@wxt-dev/module-svelte` 2.0.5, plain-TS content script), `[SKILL]` UI/UX Pro Max, `[D]` researcher discretion (CONTEXT "Claude's Discretion": popup layout).

**Phase 11 has three UI surfaces, and each has its own isolation model:**

| Surface | Runs in | Tech | Styling source |
|---------|---------|------|----------------|
| A. Toolbar popup | Extension origin (`chrome-extension://…/popup.html`), our own document | Svelte 5 via `@wxt-dev/module-svelte` `[CTX]` `[STACK]` | Plain CSS custom properties in `apps/extension/entrypoints/popup/tokens.css`, kept literal-equal to `@tran/brand` by a parity test |

## Design System

| Property | Value |
|----------|-------|
| Tool | none. shadcn-svelte is not initialized in `apps/extension`. The popup has a single interactive control (a switch) plus one link, so a native `<input type="checkbox" role="switch">` is simpler than bits-ui `[D]`. |
| Preset | not applicable |
| Component library | none (hand-built Svelte 5 components in the popup; DOM built with `document.createElement` in the content script) |
| Icon library | `@lucide/svelte` 1.45.0 in the popup only (`ShieldCheck`, `ExternalLink`, `TriangleAlert`) `[P2]`. **No icon font or SVG icon in the injected Zillow UI.** The pill is text-only. |
| Font (popup) | **Inter Variable** (`@fontsource-variable/inter` 5.3.0), bundled into the extension zip. Same stack as `[P2]`: `'Inter Variable', ui-sans-serif, system-ui, -apple-system, 'Segoe UI', sans-serif`. Fraunces is **not** bundled in the extension: the popup has no 24px+ headline, and the only brand glyph (the "T") ships as a PNG `[D]`. |
| Font (injected Zillow UI) | System stack only: `ui-sans-serif, system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`. We never load a webfont into Zillow's page. That would need `web_accessible_resources`, which is extra manifest surface for no user benefit. |
| Styling | **No Tailwind in `apps/extension`** `[D]`. Reason: the popup is a single ~320px view built from about 6 elements. Tailwind 4 would add `@tailwindcss/vite` plus a second `@theme` duplicate for one page. Plain custom properties, mirrored from `@tran/brand` and checked by the parity test, give the same token guarantee with less code. |
| Mode | Light only `[P2]`. No `prefers-color-scheme` branch in the popup. The injected pill uses fixed colors on every Zillow theme (its contrast is guaranteed against any background, see Color §B). |

**Token plumbing (popup):**
- `apps/extension/entrypoints/popup/tokens.css` declares on `:root` only the tokens the popup uses: `--color-background`, `--color-card`, `--color-foreground`, `--color-muted-foreground`, `--color-primary`, `--color-primary-hover`, `--color-secondary`, `--color-secondary-surface`, `--color-border`, `--color-border-strong`, `--color-ring`, `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-full`, `--ease-out`, `--duration-fast`, `--font-sans`. Hex values are copied literal-for-literal from `[P2]`.
- **Parity test** (Vitest, `apps/extension/tests/brand-parity.test.ts`): parse `tokens.css` and `zillow.content/style.css`, extract every hex literal and `--color-*` / `--radius-*` / `--font-*` declaration, and assert that each value exists in `tokens` exported by `@tran/brand`, under the same name where a name exists. Any hex in either file that is not a Phase 2 token value fails the test. This is how "no new hex values" is enforced mechanically. Non-vacuity: a planted fixture string containing Zillow-style blue `#006AFF` must be rejected.
- The popup's Svelte components use only `var(--…)`. No raw hex in `.svelte` files (same lint/grep rule as `[P2]`).

Exactly **3 sizes** (14 / 16 / 24) and **2 weights** (400, 600). All are a subset of the Phase 2 scale `[P2]`. Phase 2's 40px Display is not used.

|------|--------|------|--------|-------------|----------|

### B. Injected Zillow affordances (neutral, background-agnostic)

The pill sits over an unknown background, which may be a listing photo, a white card, or a future Zillow dark theme. It therefore uses a **two-tone construction**: an espresso fill and an ivory ring, or the inverse. For any background luminance L, at least one of the two tones reaches ≥3.9:1 against it. The worst case is L ≈ 0.20, where espresso gives (0.25/0.0645) and ivory gives (0.98/0.25), both ≈3.9:1. So the control's boundary always passes WCAG 1.4.11, whatever Zillow paints behind it.

| State | Fill | Text | Ring (box-shadow, outward) | Text contrast |
|-------|------|------|----------------------------|---------------|
| Dimmed (default) | `#2B1D16` espresso | `#FBF7F0` ivory | `0 0 0 2px #FBF7F0` | 15.24:1 |
| Dimmed, hover (`@media (hover: hover)`) | `#5C4A3E` walnut | `#FBF7F0` | `0 0 0 2px #FBF7F0` | 7.85:1 |
| Revealed | `#FBF7F0` ivory | `#2B1D16` espresso | `0 0 0 2px #2B1D16` | 15.24:1 |
| Revealed, hover | `#F2E9DB` sand | `#2B1D16` | `0 0 0 2px #2B1D16` | 13.53:1 |
| Focus-visible (either state) | unchanged | unchanged | Triple ring: `0 0 0 2px <state ring>, 0 0 0 4px <state fill>, 0 0 0 6px <state ring>` plus `outline: 2px solid transparent; outline-offset: 4px` | n/a |

- The focus indicator grows from 2px to 6px of alternating espresso and ivory, so it is visible on any background and differs clearly from the rest state (WCAG 2.4.7 / 2.4.13) `[SKILL focus-states]`.
- **Forced colors** (`@media (forced-colors: active)`): `background: ButtonFace; color: ButtonText; border: 1px solid ButtonText; box-shadow: none`. Focus is shown by the transparent outline, which the browser repaints as `Highlight`.
- **Dimmed card treatment:** every direct child of the card except our pill gets `opacity: 0.35 !important; filter: grayscale(1) !important;`. The pill stays at full opacity. Dimmed listing content intentionally drops below 4.5:1. This is the user-requested de-emphasis, and it is equivalent to WCAG's "inactive component" exemption. Full contrast is one click away, and the pill itself is always fully readable. The opacity is not applied to the card element itself, because that would also dim the pill.
- Nothing in Section B uses terracotta, sage, or any hue. It is espresso, walnut, sand, and ivory only. Neutral by design `[CTX]`.

## Copywriting Contract

Voice: plain, factual, nominative. **The extension dims; it never "blocks", "removes", "hides ads", or makes content "disappear".** Every surface says the user can show any card.

**Banned words in all extension UI, manifest, store listing, and install doc** (enforced by a Vitest grep over `apps/extension/**` and `docs/EXTENSION-INSTALL.md`, case-insensitive, whole word): `block`, `blocks`, `blocker`, `ad-free`, `remove`, `removes`, `official`, `Zillow's` (possessive implies affiliation). The singular word `Ad` appears only inside detection code as a label string to match, never in UI copy. "Hidden count" is the requirement's name; UI copy says **"dimmed"**.
