# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Design intelligence: UI/UX Pro Max (`src/ui-ux-pro-max/scripts/search.py --domain ux` for "drag and drop kanban keyboard alternative", "import preview confirmation bulk", "form submit success error spam", "color picker contrast", "empty state", "table mobile responsive"; `--domain product` for "CRM pipeline real estate"; `--stack svelte` for "forms inline validation dialog accessibility", run 2026-10-04). **Adopted:** every function reachable by keyboard with tab order matching visual order (the board's Move menu), a checkbox column for bulk include/exclude in import previews, loading-then-success/error on every submit, success confirmations that never stay silent, confirm before irreversible deletes, empty states with a helpful message plus an action, URLs that reflect view state (`?list=`, `?q=`, `?id=`, `#stage-…`), tables that become card lists on mobile, CSS custom properties for user-supplied theming (`style="--brand-primary: …"`, never `style="color: …"`), and the CRM product guidance of flat, minimal surfaces. **Rejected:** the product palettes (trust blue + gold; "pipeline stage colors + closed-won green"), because Phase 2 tokens are locked and stages are told apart by label and position, never by color; SvelteKit form actions (no server); `role="alert"` (Phase 3 locked one polite live region); toast confirmations (Phase 3/5 persistent-inline feedback model); validate-on-blur (Phase 3 locked validate-on-submit). **No new hex values.**

**Sources legend:** `[CTX]` 08-CONTEXT.md (locked), `[P2]` approved 02-UI-SPEC.md, `[P3]` approved 03-UI-SPEC.md, `[P4]` approved 04-UI-SPEC.md, `[P5]` approved 05-UI-SPEC.md, `[P6 draft]` 06-UI-SPEC.md (draft, written in parallel; aligned on board breakpoints and selected-state styling), `[REQ]` REQUIREMENTS.md / ROADMAP.md (AGT-01..07), `[STACK]` CLAUDE.md, `[RES]` `.planning/research/*.md`, `[CODE]` existing repo, `[SKILL]` UI/UX Pro Max, `[D]` researcher discretion (CONTEXT "Claude's Discretion" or a UI detail CONTEXT does not address).

**Honesty rules for this phase (apply to every string below):**
1. "Import from email" always means **paste**. Tran never connects to an inbox, and no string implies it does ("Copy the lead email from your inbox and paste it here").
2. The inquiry page says leads are **emailed to the agent by Web3Forms and are not stored by Tran**.
3. No SMS or TCPA-style consent language anywhere. The inquiry consent is exactly "I agree to be contacted about my inquiry." `[CTX]`
4. Tran is never a brokerage. Profile, inquiry and draft copy say the details come from the agent; Tran is the software.
5. Agent brand colors apply to **accents in agent-branded output only** (Phase 8 `BrandPreview`, Phase 9 reports). Tran's own UI never takes agent colors. A color that fails its contrast check is replaced by a Tran token, and the UI says so.
6. "Sent" in the CRM always means "marked as sent by you". Tran sends nothing `[P5]`.
7. Sample contacts are unmistakable: every card, row and detail page carries the Phase 4 "Sample data" chip.

## Shape, Elevation, Motion

Phase 2 tokens `[P2]`: `--radius-md` 8px (buttons, inputs, selects, task rows, logo preview box, share-link field), `--radius-lg` 16px (board cards, board columns, section panels, dialogs, list rows on mobile, alerts, inquiry form panel), `--radius-full` (badges, chips, count pill). `--shadow-card` on section panels and the inquiry form panel; board cards use **no shadow at rest** (1px `border` only, so a dense board stays calm) and `--shadow-card-hover` while being dragged or when their Move menu is open; `--shadow-card-hover` on dialogs and menus.

- Card moves (drop, Move menu, Undo) re-render **instantly**. No FLIP or slide animation: moving a card is content change, not decoration, and an animated reflow across five columns is the kind of multi-element motion the skill rules out `[SKILL excessive-motion]`.
- Drag feedback: the source card switches to `surface` fill with a 2px dashed `border-strong` outline and the text "Moving…" replacing its meta line; the browser's own drag image follows the pointer. Valid columns show a 2px dashed `border-strong` outline; the column under the pointer shows the 2px solid `primary` outline and the "Drop to move to {Stage}" line. All of these are state changes with no transition.
- Dialogs and the Move menu follow Phase 3/5 (150ms opacity fade under `motion-safe:`, instant under reduced motion) `[P3]` `[P5]`.
- In-flight buttons (Saving…, Checking…, Importing…, Sending…) use Lucide `LoaderCircle` 16px `motion-safe:animate-spin`, keep their rest width `[P3]`.
- Brand color preview updates on every `input` event with no transition.
- No scroll-triggered motion, no skeleton shimmer. Lists hydrate behind a static "Loading your contacts…" line (Label 14/400 muted) for the first `liveQuery` result.
