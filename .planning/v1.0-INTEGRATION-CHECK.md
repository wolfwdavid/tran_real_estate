## Flows traced (all complete)
- Renter: portal pick, ?source=sample hand-off in (app)/+layout.svelte, or key paste -> vault -> data/platform.ts bindRentCastVault -> gateway. Search state uses renter data/requests.ts and runtime.requestSpend. Saved search -> shortlist -> OutreachSection -> GenerationPanel (feature `renter-outreach`, prompt `renter/outreach.v1`). Exits are gated by the Fair Housing post-check.
- Investor: analyzer -> AutofillButton -> investor-port -> runtime.requestSpend. Cap prompt is CapConfirmDialog, rendered once by DataShell. Deals and compare -> `/investor/memo/?id=` -> memoFactsForDeal -> GenerationPanel with memo post-checks. Facts come from analyze(deal.inputs), and a stale hash flags edited deals. Print goes via `/print/memo/?id&memo`.
- Agent: web3forms-sink builds the lead with buildLeadBlock; paste-to-leads.ts parses it with the same parseLeadBlocks (shared @tran/core contract) -> import-commit -> contacts and pipeline -> tasks and today -> FollowUpComposer (GenerationPanel, `agent-followup` prompt registered in followup-prompt.ts, CAN-SPAM tokens appended locally). Studio listing, social and reel go through GenerationPanel with studio post-checks. Snapshot uses snapshot-data.ts -> runtime.requestSpend, save-gate, then `/print/snapshot/`.
- Platform backup: backup-registry.ts DEFAULT_TABLES aggregates the Phase 4 (ledger, savedSearches, searchSnapshots, dataPrefs), 5 (aiArtifacts), 6, 7, 8 and 9 tables. apiCache and meta are excluded, and the vault lives in a separate DB. db.ts versions 1-7 are append-only and match the store blocks. The vault never enters the export, with a key-shape scan as defence in depth. Agent profile scan-exempt paths are declared.
- Network egress: the only fetch call sites are rentcast/client.ts, ai/providers/http.ts, web3forms-sink.ts, analytics/beacon.ts and the service worker (same-origin GET precache only). All are covered by the buildCsp connect-src list (RentCast, 4 AI hosts, Web3Forms, plus the optional analytics host). The analytics host is added only via resolveAnalytics(), which svelte.config.js reads. The layout gate on `__ANALYTICS_HOST__ && __ANALYTICS_WEBSITE_ID__` is a vite define fed by the same resolver, so config, CSP and beacon share one source. Beacon honours GPC/DNT. ci.yml passes the repo vars to the root leg only.
- AI: every AI surface (renter outreach, investor memo, agent follow-up, 4 Studio tools) mounts GenerationPanel. Prompts all pass registry.buildPrompt (guardrail, PII redaction, hash). Keys come from the vault via ai/setup.ts. The no-auto-send and import-graph tests guard AI-04.
- Extension (Phase 11): standalone. privacy/+page.svelte has `<h2 id="browser-extension">`, which matches PRIVACY_URL (`/legal/privacy/#browser-extension`); extension-docs.test.ts pins both. Root `verify` ends with ext:build, ext:assert, ext:test:browser and ext:e2e. ci.yml runs the same gates on the root leg, and extension-release.yml exists.
- Route reachability: every page route has at least one inbound link (nav files, hubs, marketing). Service worker precache is by pathname, so query-string routes (listing, memo, print) work.
